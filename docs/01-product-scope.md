# 01 产品定位与范围

## 1. 背景与痛点

用户计划运营公众号、头条号等文字或视频自媒体账号。现有通用 AI 助手能够辅助创作，但使用中存在重复介绍账号、人设、提示词和创作步骤的问题，内容与素材也难以形成持续运营的工作环境。

Creator-AI 需要把重复的创作配置持久化，并让系统根据账号、专家、技能和计划组织内容生产。它辅助创作，不承诺消除观点、素材、事实核验和人工判断的必要性。

2026-11-02 范围调整：按用户明确要求，专家、Skills、专家团以 WorkBuddy 的完整功能语义为对齐目标。采用独立实现，不复制其私有代码和内容；不能以“提示词表单 + 三个固定技能”代替。范围、现状与验收差距见 [能力对齐计划](./13-workbuddy-capability-plan.md)。

## 2. 产品定义

> 可自部署、可自选模型、围绕账号和专家持续工作的 AI 自媒体创作工作台。

第一阶段服务个人创作者，优先解决公众号图文创作，不先做收费 SaaS 或大型团队运营系统。自部署不等于数据完全留在本地：调用云端模型时会发送被选中的指令、素材和内容，需要向用户明确提示。

## 3. 核心价值

1. **少重复说明**：账号定位、人设、专家指令和技能配置可以复用。
2. **创作可持续**：素材、选题、内容历史和创作计划在同一系统里管理。
3. **结果可编辑**：生成稿不是最终答案，用户可以改写、比较版本、审核和导出。
4. **运行可追溯**：能知道使用了哪些配置、素材、模型，执行到哪一步，为什么失败。
5. **能力可迁移**：用户掌握账号配置与内容，第一版支持备份和内容导出，后续完善配置交换格式；模型接入不锁定单一供应商。

## 4. 核心用户旅程

```text
首次初始化管理员和模型
            |
建立账号档案与作者人设
            |
选择或配置单专家 / 专家团、Skills、参考素材
            |
手动填写主题 / 从已确认选题创建定时计划
            |
生成大纲 -> 可选人工确认 -> 正文 -> 检查 -> 排版
            |
编辑、比较版本、审核
            |
导出内容与素材
            |
后续：平台草稿同步 / 已授权的受控发布
```

首页和导航围绕内容、专家与任务组织。对话是修改内容的一种交互形式，不是保存全部业务状态的唯一载体。

## 5. v0.1 范围

| 能力     | 范围                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 使用方式 | 单实例、单管理员起步；保留清晰的数据归属，不实现完整多租户                                |
| 账号     | 可建多个平台账号档案，默认专家、作者人设、栏目和创作要求                                  |
| 专家     | 独立中心，角色身份/指令、引导创建、复制编辑、版本、试运行、包管理与默认绑定               |
| 专家团   | 主理人与独立成员、任务依赖、并行/串行、消息汇报、产物汇总、失败与恢复；不是单模型模拟多人 |
| Skills   | 独立技能库、SKILL.md 与资源、创建/导入/导出/版本、按需加载与受控工具；不任意执行上传代码  |
| 素材     | 手动录入、文本或 Markdown 导入、图片上传、分类、搜索和显式选择                            |
| 创作     | 公众号文章为主，支持通用文本与口播稿；固定工作流，不做拖拽编排                            |
| 内容     | 富文本编辑、版本保留、局部改写、审核、HTML 与素材导出                                     |
| 计划     | 手动任务、定时创作、选题队列、时区、预算和并发限制                                        |
| 模型     | 接入经过验证的少量文字模型供应商，配置、连接测试、调用记录                                |
| 运维     | 登录、安全存储、后台任务、日志、持久化、备份恢复、基础站内提醒                            |

以上是目标，不是当前开发预览的全量已完成功能。已开放模型连接、只读 Skill 与独立成员阶段执行，动态团队与真实服务商质量等仍待验收，见 10、13、14。允许创建“头条号”等账号档案，不等于已完成其专用排版、数据分析或发布适配。图文的“图”首先指用户上传和选择图片，不强制包括 AI 生图。

## 6. 后续范围

- v0.2：经核验的平台草稿接入、审核后受控发布、平台改编、外部通知、辅助偏好提取。
- v0.3：配图、配音、字幕、素材视频合成、更多平台和必要的小团队协作。
- 完整 AI 视频生成需要单独验证模型效果、成本、素材权利和资源需求。

## 7. 第一版非目标

- 全平台自动登录、无限账号分发、绕过平台审核或验证码。
- 完全无人审核的内容发布，以及自动保证事实准确的承诺。
- 与自媒体创作无关的通用多智能体平台、任意第三方脚本直接执行环境。AI 专家团属于必做范围，不能据此排除。
- WorkBuddy 私有市场服务或商业内容镜像；本项目独立的分享/发现能力按能力对齐计划实现。
- 自建模型训练、GPU 推理集群、复杂 RAG 和独立向量数据库。
- 多租户计费、复杂组织权限、多人实时协作编辑。
- 热点抓取大全、任意网页采集、完整视频编辑器。

## 8. 自动化与人工边界

- 自动生成默认进入待审区，不自动取得发布授权。
- 需要人工确认的工作流可以暂停；不占用 Worker 一直等待。
- 定时成稿优先消费已确认的选题；选题不足时暂停该次执行并提醒，不凭空扩大任务数量。
- 标注缺少来源的说法，不能把 AI 自检通过等同于事实保证。
- 人设不能作为编造经历、资历或真实人物背书的依据。
- 审核针对具体内容版本；修改正文、标题或发布素材后，旧审核不能授权新版本发布。

## 9. 成功标准

首个真实使用验证周期建议为两周，记录以下指标，不预设未经验证的提升幅度：

- 从给出主题到可用稿件的人工操作时间。
- 生成稿经过有限修改后可发布的比例。
- 重复纠正人设、口吻和结构的次数。
- 每篇稿件的模型费用估算、失败重试次数和耗时。
- 重开页面、重启服务后，任务与稿件能否正确恢复或明确提示状态。

v0.1 的关键验收结果是：用户配置一次账号和专家后，可以持续得到可编辑、可审核、可导出的内容，而不是每次重新解释相同背景。
