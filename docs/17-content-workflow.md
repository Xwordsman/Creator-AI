# 17 内容编辑、版本、审核与导出

> 更新：2026-11-09 · 0.0.1 开发预览。本文约定内容闭环；当前稿的 AI 讨论与批注修改见 18，实际测试和本地升级记录见 10。不是平台发布、完整排版或真实模型质量验收。

## 1. 使用路径

`创作记录 → 已完成的候选稿 → 加入内容库 / 编辑 → 保存新版本 → 提交审核 → 人工通过 / 要求修改 → 导出`

- 内容库是一级导航，`/contents` 列表、`/contents/:id` 编辑台。
- 必须显式加入，升级不自动把历史任务转换为内容。只接收本人 `succeeded` 且正文通过白名单校验的任务。
- 每条来源任务最多对应一篇内容；重复点击或并发加入返回同一内容。不同 AI 修改分支可以各自加入，互不覆盖。
- v1 复制候选标题和正文；后续人工修改与审核均在内容模块，不修改 `creation_runs.output/snapshot` 或模型调用账本。
- 任务页的“继续创作”仍以该任务的原始候选稿为上下文，不会自动读取内容库人工稿。基于当前人工稿的讨论、批注和选择改写从文章编辑台“打开 AI 协作”进入，见 [18 文章协作编辑](./18-article-collaboration.md)。协作任务不能作为另一篇候选稿加入内容库。

## 2. 数据与并发

新增四张表，无历史业务列变更：

| 表                   | 用途                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| `content_items`      | owner、来源任务、账号名称/平台快照、不可改的模拟标识、当前标题/版本、审核状态、修订号 |
| `content_versions`   | `(content_id, version)`，不可变标题/正文、来源类型、恢复来源、修改说明、时间          |
| `content_reviews`    | 具体版本、送审/通过/修改要求、操作者、意见、时间；追加审计                            |
| `content_operations` | 内容内幂等键、输入摘要、原操作结果元数据；用于可靠重试                                |

迁移为 `ContentWorkflow1793923200000`。当前版本外键延迟到事务提交校验，避免半篇内容落库。down 拒绝破坏证据，需要经过验证的备份恢复。

- `version` 仅在保存/恢复时递增；`revision` 在保存/恢复/审核时均递增。
- 写入必须带 `baseRevision` 和 16–128 位 `Idempotency-Key`，先锁内容行，再检查幂等收据，再检查修订号。
- 相同键和输入回放原操作对应的版本/元数据，哪怕随后已有新版本。相同键不同输入返回 `409 IDEMPOTENCY_CONFLICT`。
- 不同键基于旧修订写入返回 `409 CONTENT_CONFLICT`，不静默合并或覆盖。失败事务不产生版本、审核或收据。
- 恢复历史版本新增一版，不回拨版本号、不删除中间版本，不继承旧审核。
- 版本和审核列表分页；版本列表不批量返回正文，正文通过单版本接口读取。

## 3. 审核语义

```text
draft / changes_requested --submit--> pending_review
pending_review --approve--> approved
pending_review --request_changes--> changes_requested
任何状态 --save / restore--> draft + 新版本
```

本轮加入内容后初始为 `draft`，由用户显式送审。运行输出中的历史 `reviewStatus: pending_review` 仅表示 AI 候选稿未审，不能当作内容库已经提交审核。

- 审核绑定当时的准确版本与修订号；修改原因必填，送审/通过意见可选。
- 当前为个人工作空间，所有动作由本人完成，不宣称编辑/审核人角色分离、团队权限或四眼审核。
- 模拟来源或输出任一标为 mock，内容永久 `isMock=true`。修改正文和恢复均不能洗掉来源。
- 模拟稿可编辑、送审、要求修改和明确确认后导出，但不能 `approve`，API 返回 `422 MOCK_NOT_APPROVABLE`。
- 审核通过只是用户记录的结论，不代表系统验证了事实、版权、合规或平台发布资格。

## 4. 正文安全边界

前后端共享白名单：doc → paragraph / heading(level 2、3) → text。仅允许这些字段，不接收 marks、原始 HTML、链接、图片、附件或任意 attrs。

- 标题 trim 后 1–300 字符；正文 1–200 块，每块最多 100 个文本节点，每文本节点最多 20,000 字符，总文本最多 200,000 字符。
- 空正文段落允许，空标题段落不能保存；编辑中的空标题和空 heading 可保留到本地会话，不能因此放宽服务器保存边界。
- 内容路由 JSON 上限 2 MiB，其余普通请求保持 64 KiB；大输入先由解析器拒绝，再由共享 Schema 校验。
- Tiptap 仅开放正文、二/三级标题及撤销/重做；粘贴移除不支持样式。界面不使用 `v-html` 渲染作者内容。

## 5. 浏览器编辑保护

- 未保存编辑提示离开/刷新，内容内路由切换也确认；服务端写入不自动触发。
- 本地草稿和未确认请求保存在 `sessionStorage`，按用户和内容隔离，不是服务器备份，也不保证关闭浏览器后的持久化。
- 提交前冻结准确请求体与幂等键并保存；无法保存请求标识时不提交。
- 网络/5xx/408/429、畸形 4xx 与无效成功收据等不明确结果锁定编辑，提供显式“原样重试并核对”，不自动换键重发；刷新后仍保留待确认操作。损坏待确认记录阻止写入，不直接覆盖或清理。
- 保存成功收据先校验内容身份、版本、正文与来源，再应用已确认稿并读取服务器最新内容；后续读取失败仍保留已保存稿。旧幂等收据不是“最新”的证明。迟到响应不能更新另一个页面/用户的状态。
- 明确放弃本地稿后读取服务器失败，仍保留原本地恢复记录；初次读取失败后的重试会继续恢复原本地稿。仅有效读取成功后才清理相应编辑记录。
- 冲突保留本地编辑，用户可下载本地 JSON 备份，再明确放弃并读取服务器版本后人工合并；不提供自动三方合并或备份导入。
- 本地备份不是服务器保存版本，不具备审核结论，包含私人正文，应自行保管。

## 6. API

所有接口继承会话、owner 校验、同源和写入 CSRF，JSON 正常响应沿用 envelope。

| 方法与路径（`/api/v1` 前缀）          | 输入 / 结果                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------ |
| POST `/contents`                      | `{sourceRunId}`，201，按来源唯一幂等，返回当前 item + version                  |
| GET `/contents`                       | 分页内容元数据                                                                 |
| GET `/contents/:id`                   | 一致读取当前 item + version                                                    |
| GET `/contents/:id/versions`          | 分页版本元数据，不含正文                                                       |
| GET `/contents/:id/versions/:version` | 准确不可变版本及正文                                                           |
| POST `/contents/:id/versions`         | `{baseRevision,title,document,note?}`，幂等键必填，200                         |
| POST `/contents/:id/restore`          | `{baseRevision,version}`，幂等键必填，200                                      |
| GET `/contents/:id/reviews`           | 分页审核历史                                                                   |
| POST `/contents/:id/reviews`          | `{baseRevision,action,note?}`，幂等键必填，200                                 |
| POST `/contents/:id/export`           | `{version,format,acknowledgeUnreviewed?}`，200 原始附件；失败沿用错误 envelope |

## 7. 导出

支持 JSON、Markdown、安全独立 HTML，导出请求准确版本，不包含编辑器未保存内容。

- 只有“非 mock + 当前版本 + 当前状态 approved”视为当前有效通过。历史、模拟或未审版本必须 `acknowledgeUnreviewed=true`，否则 `422 EXPORT_ACK_REQUIRED`。
- JSON 含来源、版本、mock、approved 与 warnings；Markdown/HTML 含醒目的模拟/未审提示、来源和版本。
- Markdown 转义 HTML 和语法字符，保留文本与段落标题结构。HTML 从白名单节点构造并转义文本，固定样式、禁止脚本/资源/表单的 CSP，不加载外部图片或字体。
- 附件固定 UUID/版本文件名，`no-store`、`nosniff`；不接受客户端指定任意文件路径或 HTML 模板。
- HTML 是通用人工交接文件，不保证公众号/头条编辑器的样式粘贴效果，不包含平台图片上传、封面、平台草稿推送、授权、排期或自动发布。
- 导出不产生发布记录，不把下载成功当作平台发布成功。
