# 08 开发路线与验收

> 路线表达依赖顺序，不是未经评估的工期承诺。2026-11-02 按 D-011 将完整专家、Skills、AI 专家团纳入必做范围。当前已交付配置/包管理、受限模型/团队执行、草稿分支修改与人工内容编辑/版本/审核/导出，尚无里程碑整体验收完成，详见 [实施状态](./10-implementation-status.md)。

## 1. 实施顺序

```text
M0 技术验证
   -> M1 工程与安全基础
   -> M2 账号、专家/专家团、Skills 与素材
   -> M3 手动创作、编辑、审核与导出
   -> M4 定时任务、故障恢复与试运行
   -> v0.1 验收发布
   -> v0.2 平台接入
   -> v0.3 媒体扩展
```

先交付端到端路径，不先铺满所有菜单的空页面。每个里程碑都要包含失败场景和测试。

当前已交付账号、专家/团队配置、独立技能库、版本/资源快照、受限 ZIP、只读候选、成功稿分支修改、受限动态团队和独立人工内容闭环。模型适配、按需 Skill 工具、阶段执行及动态规划/答复恢复通过本地 HTTP fixture 与真实 PostgreSQL/Redis 集成；编辑冲突、版本/审核和安全通用导出已有集成与桌面/手机测试。真实服务商质量、完整自主协作、平台图片/样式兼容和 Docker 部署仍未验收。

能力执行按 [13 号计划](./13-workbuddy-capability-plan.md) 分为 C1 配置与包管理、C2 单专家和按需 Skill 执行、C3 独立专家团、C4 完整创建/分享与工具体验。C2/C3 是 M2/M3 的必做依赖，不得把专家团改为可选远期事项；Docker 与安全验证可并行推进，不用等待界面铺满。

## 2. M0 技术验证

目标：用最小验证消除关键不确定性，不做完整产品 UI。

- 核验并锁定 Node.js、前后端框架、ORM、编辑器、队列和镜像的兼容版本及许可证。
- 验证 Tiptap 文档保存、HTML 清理、公众号样式导出和实际粘贴效果。
- 确认首批模型供应商及文字调用方式；先用适配器桩，再用受控额度验证真实接口。
- 验证 NestJS API 与 Worker 分进程、PostgreSQL 记录、BullMQ 执行、SSE 进度。
- 选择会话与安全引导实现，验证同源 Cookie 和 SSE 鉴权。

退出标准：关键技术链路通过或明确记录替代方案；文档与版本锁定一致。模型未配置时明确失败，不假装生成；真实平台排版验证不能用浏览器预览代替。

## 3. M1 工程与安全基础

交付内容：

- pnpm workspace、前端基础路由、后端模块结构、API/Worker 双入口。
- Docker Compose、Caddy、持久化目录、环境示例与初始化说明。
- 数据库迁移、首个管理员、登录会话、统一错误与结构化日志。
- 测试与 CI 基础，模型桩、健康检查与受保护文件访问基础。

退出标准：全新环境可按说明初始化并登录；重建容器不丢管理员；数据库与 Redis 不暴露公网；未登录不能访问业务数据；迁移不会由多个实例竞争执行。

## 4. M2 账号、专家/专家团、Skills 与素材

交付内容：FR-03 至 FR-07、FR-14，以及 FR-21/FR-22 的专家团与能力包生命周期。

- 创建多个账号档案与作者人设。
- 独立专家中心：身份/方法、零到多项 Skills、引导创建、资料转专家、复制、启停、版本与默认绑定。
- 独立技能库：SKILL.md/资源、预览导入导出、版本与固定引用；真实按需加载及工具授权审计。
- 专家团：唯一主理人、独立成员、成员配置与任务依赖；保存成员运行、消息、原始产物与成本。
- 基础素材录入、文本与图片上传、标签搜索和账号隔离。
- 专家试运行与模型连接测试，展示用量及安全边界。

退出标准：同一专家可服务两个账号且风格与素材隔离；用户新建的 Skill 无须改源码就能被真实加载；历史配置可追溯；模型密钥不出现在前端响应或普通日志中；未授权工具无法调用。专家团需要独立上下文、真实成员调用、并行/依赖、回报和汇总证据，不能以配置表单或一次多角色输出通过验收。

## 5. M3 创作与内容闭环

交付内容：FR-08 至 FR-11、FR-13，以及真实工作台状态。

- 任务、步骤、Outbox 与有限重试；运行快照和重要事件。
- 先完成 ModelInvocation、预算预留、结果未知与核对，再开放付费模型；团队复用同一套可靠调用语义。
- 主题与素材生成、大纲确认、正文、疑点标记、局部改写。
- Tiptap 编辑、冲突检测、内容版本、审核和 HTML/素材导出。
- 页面离开与 SSE 重连后恢复当前状态，生成结果不覆盖用户编辑。

退出标准：用户只输入主题就能复用账号和单专家/专家团完成可编辑草稿；成员结果与来源可追溯；人工确认跨重启可恢复；取消、失败与未知结果不会盲目重复扣费；导出目标明确，版本与审核语义正确。

## 6. M4 计划与可靠性

交付内容：FR-12、FR-15 和 v0.1 运维完整性。

- 选题确认队列、定时计划、时区、漏跑策略、额度与并发上限。
- 幂等触发、选题预留、取消、失败对账和结果未知状态处理。
- 站内提醒、用量统计、备份恢复与部署升级说明。
- 故障演练、核心 E2E 和两周真实创作试运行。

退出标准：相同计划时点不重复创建稿件，停机恢复不集中补跑；备份可以恢复；数据不因容器重建丢失；试运行记录可用稿比例、编辑时间、重复修正与成本。

## 7. v0.1 验收场景

| 编号  | 场景                 | 通过标准                                                                        |
| ----- | -------------------- | ------------------------------------------------------------------------------- |
| AT-01 | 首次部署与重启       | 安全初始化管理员，重启后登录与配置有效，无默认公开密码                          |
| AT-02 | 两账号共用专家       | 各自遵循人设，不读取另一个账号的私有素材                                        |
| AT-03 | 专家和技能改版       | 新运行使用新配置，旧任务的输入版本与结果仍可追溯                                |
| AT-04 | 一次主题持续创作     | 无需重新描述人设，完成草稿、修改、审核与导出                                    |
| AT-05 | 离开页面与断线       | 后台继续；重开页面看到当前状态和已保存正文                                      |
| AT-06 | 人工确认与重启       | 大纲确认期间不占用运行进程，重启后可继续且不重复确认                            |
| AT-07 | 内容编辑冲突         | 并发修改返回明确冲突；生成候选稿不会覆盖用户正文                                |
| AT-08 | 审核后修改           | 新版本回到未审核状态；旧审核只对应旧版本                                        |
| AT-09 | 任务重复提交         | 相同幂等键得到同一业务运行；不同输入复用键被拒绝                                |
| AT-10 | 计划重复触发与缺选题 | 一次时点只产生约定数量任务；缺选题时记录原因并提醒                              |
| AT-11 | 停机与恢复           | 按 skip_missed 跳过漏跑时点；未确认的外部结果不盲目重发                         |
| AT-12 | 模型超时和限流       | 有限退避、费用记录、明确失败或待核对，不无限调用                                |
| AT-13 | 权限与恶意素材       | 素材中的指令不能获取密钥、跨账号读取或触发未授权工具                            |
| AT-14 | 文件与 HTML          | 超限或危险上传被拒绝；预览和导出不执行注入脚本                                  |
| AT-15 | 备份恢复             | 隔离恢复后账号、版本、素材可读，任务副作用不会自动重放                          |
| AT-16 | 真实导出             | 标题、段落、图片和主要样式可用于目标平台，已知限制有说明                        |
| AT-17 | 专家与 Skill 能力包  | 零 Skill 合法；自定义技能可按需加载；包预览无写入，冲突原子回滚，脚本不自行获权 |
| AT-18 | 专家团协作           | 成员独立调用，阶段/依赖正确，消息与原始结果可追溯，主理人不伪造成员输出         |
| AT-19 | 专家团故障恢复       | 取消停止新派工，成员失败可见，预算受控，重启不重发结果未知的外部调用            |
| AT-20 | 围绕成功草稿修改     | 冻结原配置、保留原稿，独立预算/账本、分支来源可追溯，相同键不会重复创建任务     |

能力对齐的细分验收与当前通过范围以 WB-01 至 WB-11 为准。AT-17 的配置、包管理、只读按需加载，以及 AT-18/19 的独立成员、阶段依赖、预算、取消与未知结果恢复已有协议和数据库测试；动态派工、追问与持久化交互见 16。AT-20 的不可变分支修改已通过协议、数据库与桌面/手机测试。AT-07/08 的编辑冲突、准确版本审核/失效/恢复及 AT-14 的文本/通用 HTML 注入拒绝与转义已有测试，具体内容闭环见 17；AT-14 不代表未来图片上传已验，AT-16 的目标平台图片与主要样式仍未通过。不代表真实模型质量、完整聊天、第三方运行兼容或生产故障演练已经通过。当前执行子集见 14–17，M3 及完整验收仍未完成。

## 8. v0.2：平台接入

先选择一个具备实际验证条件的平台，不同时承诺全部平台。完成账号权限核验、草稿提交、素材上传与格式适配，再考虑受控发布。

额外发布门槛：明确用户授权、锁定审核版本、平台请求幂等或核对策略、发布结果查询、失败与未知状态、修改后的重新确认。没有官方能力或稳定接入条件时，继续保留手动导出。

## 9. v0.3：媒体与协作

先验证脚本 -> 配音/字幕 -> 已授权素材合成的链路，再独立评估生成式视频。CPU 密集处理进入专用 Worker，不阻塞普通创作 API。

这里的“小团队协作”指多名真人用户、组织权限和协同编辑，不是 AI 专家团。前者与偏好建议、语义检索等按真实需求推进；后者已经由 D-011 确认为当前必做目标。

## 10. 发布完成标准

- 功能需求和对应验收场景通过，重大故障与安全问题已处理。
- CI 中类型、格式、单元、集成和关键 E2E 检查通过。
- 可从干净环境部署，迁移、持久化、备份与恢复说明经过实践验证。
- 依赖版本与许可证清单明确；开源许可证已选择；未包含真实凭证或私有素材。
- 已支持、未支持和待验证的平台能力清晰展示。
- 文档、配置示例、接口契约和实际代码一致，不以设计图充当已实现证明。
