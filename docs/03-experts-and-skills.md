# 03 专家与 Skills

> 2026-11-02 按 D-011 修订。完整专家、Skills、专家团是确认目标；当前配置与只读 Agent/阶段团队执行子集见 10、14，剩余差距见 [能力对齐计划](./13-workbuddy-capability-plan.md)。

## 1. 定义与边界

专家中心是解决“每次重复输入背景和提示词”的核心入口，必须独立实现，不能被账号人设或模型聊天设置替代。

| 概念     | 回答的问题                           | 示例                             |
| -------- | ------------------------------------ | -------------------------------- |
| 账号档案 | 给谁创作、在哪里使用、面向什么受众   | 面向普通人的 AI 科普公众号       |
| 作者人设 | 用什么身份视角、口吻和表达习惯       | 通俗、克制、不编造亲身经历       |
| 专家     | 谁负责执行、擅长什么、遵循什么方法   | 公众号主笔、选题编辑             |
| 专家团   | 谁统筹、谁独立完成各项工作、如何协作 | 主编 + 资料员 + 主笔 + 审校      |
| Skill    | 可以复用的具体创作能力               | 标题生成、素材整理、文章排版     |
| 工具     | 具有外部访问或副作用的执行能力       | 读取授权素材、调用模型、导出文件 |
| 工作流   | 步骤如何组合、何时暂停、如何恢复     | 大纲 -> 正文 -> 检查 -> 排版     |
| 模型配置 | 用哪个供应商能力完成哪种任务         | 某供应商的文字生成模型           |

一个专家可以服务多个账号，但不能因此读取其他账号的私有资料。专家也可有默认身份与口吻；账号人设优先决定这次内容的表达，两者不是同一个对象。单专家允许绑定零到多项 Skills。

## 2. 专家配置

建议字段分组：

- 身份：名称、描述、头像、标签、启用状态。
- 方法：职责、工作指令、质量要求、禁止行为。
- 能力：绑定的 Skill 版本、可用工作流、工具白名单。
- 上下文：允许使用的参考素材或样文，不默认加载所有历史内容。
- 模型：可选默认模型、生成参数与单次任务预算。
- 生命周期：当前版本、更新说明、创建人与更新时间。

更新专家创建新版本。已经运行或排队的任务保留创建时快照；如需使用新配置，应显式创建新运行。管理员安全撤权在实际执行前重新检查，旧快照不能绕过当前撤权。

当前已支持名称、职业、简介、指令、标签、推荐问法、引导语、启停、最大轮次及技能/预加载配置；账号默认专家、固定技能版本引用和定义历史恢复也已实现。头像、模型默认值、引导创建、资料转专家和独立试运行仍待实现。账号可直接导入人物卡、写作卡和范文作为写作资料，区别于专家与 Skill，详见 [20](./20-account-writing-cards.md)。

## 3. Skill 定义

Skill 是可保存和分层加载的能力包，不是固定枚举或必定运行的脚本。基本结构：

```text
article-outline/
  SKILL.md
  references/    可选说明资料
  assets/        可选模板与资源
  scripts/       可选脚本；存在不等于可执行
```

`SKILL.md` 示例（项目自有示例，不是第三方提示词）：

```markdown
---
name: article-outline
description: 根据主题与目标读者整理文章结构，在正式写作前使用。
---

先说明文章要解决的问题，再组织论点与段落。缺少依据时标注待核实，不编造引用。
```

名称与描述用于发现；触发后加载正文，参考资料再按需读取。不是每个 Skill 都需要输入输出 JSON Schema，结构校验应由具体工作流/工具适配层定义，不能只依赖 TypeScript 或提示词。

工具授权采用求交而非叠加：实际可用工具不能超出系统允许集合、用户/账号权限、专家白名单、Skill 白名单及本次任务授权中的任何一项。技能声明需要某个工具，并不等于获得该工具的权限。

当前保留三项只读内置定义，并支持自定义/导入 Skill、编辑指令、版本、启停、资源查看和导出。版本与资源存在 PostgreSQL JSONB 中。专家包内技能使用 `包名:技能名` 命名空间；导入冲突不能覆盖已有定义。

已按 WorkBuddy 随附规范实现受限专家/技能 ZIP 格式解析，不等于兼容其运行时、工具接口或市场。完整格式约束和导入/导出限制见 13。内置技能“复制指令”不复制附件；编辑已导入技能保留已有资源。

运行状态分开保存：

| 状态            | 含义                   | 当前实现                              |
| --------------- | ---------------------- | ------------------------------------- |
| available       | 当前专家可选择的技能   | 保存 key 与任务时版本快照             |
| preloaded       | 配置为启动预加载的子集 | 仅配置意图，不是加载证明              |
| loaded          | 实际加载过正文的技能   | execution 中按成员记录；mock 为空     |
| tool invocation | 工具实际执行与结果     | 只读加载/资料及拒绝记录，版本来自快照 |

禁止事项：

- 不执行用户上传的任意 JavaScript、Python 或 Shell 脚本。
- 不允许技能自行读取全部环境变量、服务器文件或模型密钥。
- 不允许“发布文章”等高权限动作伪装成普通写作技能。
- 不因为模型请求调用某工具，就跳过服务端校验。

ZIP 中的脚本和二进制目前只存档，不解包落地、不安装依赖、不授予权限。安全沙箱及受控工具适配是执行阶段的独立交付，不因 Web 应用运行在 Docker 中就自动安全。

### 专家团定义与协作

专家团包含团队 SOP、唯一主理人、2–12 个成员（含主理人）。成员独立保存身份、指令、可用与预加载 Skills、轮次；从已有单专家复制的是当前定义快照。

当前按结构化阶段执行：同阶段最多 3 位成员并行、阶段间串行；主理人不在被派工成员列表中，最后独立汇总。导入的自然语言 SOP 不自动转成已授权计划。

当前持久化成员运行、依赖、派工回报与原始交付；每位成员独立模型上下文/调用。未选择模型的团队仍返回 `TEAM_RUNTIME_UNAVAILABLE`，选择连接后可执行阶段计划，也可显式启用动态提案、批准派工、追问、反馈重规划与继续。动态模式范围和预算见 [16](./16-dynamic-team-collaboration.md)，仍需真实模型质量评价。

## 4. 上下文组装

上下文不是简单拼接所有历史记录。任务创建时确定作用域、来源和版本，执行时按令牌预算选择必要内容。

建议层次：

1. 系统约束与权限边界：不可被专家、素材或用户正文覆盖。
2. 工作流与专家职责：决定本次任务的步骤和输出契约。
3. 账号定位与作者人设：决定受众、表达和内容边界。
4. 本次主题与补充要求：在前述边界内细化目标。
5. 选定素材与相关历史：作为引用数据，不作为权限指令。

表达参数的合并规则可以是“本次显式参数 > 账号配置 > 专家默认值”，但不能覆盖系统安全规则与工具授权。禁止事项发生冲突时采用更严格规则，必要时要求用户修正配置。

专家的“默认幽默风格”不能压过账号明确要求的“严肃克制”。用户临时说明可以调整文章字数，但不能让外部资料中的指令获取平台凭证。

模型路径已按此组装受限上下文，协议和数据库测试不等于模型实际遵循或创作质量验收。mock 仍只生成固定模板，不证明技能选择或团队协作发生。

## 5. 执行与恢复

```text
校验账号、专家、技能、素材权限与预算
                  |
保存配置快照与任务步骤
                  |
Worker 执行当前可运行步骤
                  |
校验输出 -> 保存候选结果与调用记录
                  |
需要确认？-- 是 --> 保存暂停状态，释放 Worker
    |                     |
    否                 用户确认后重新入队
    |                     |
    +--------- 下一步 ----+
                  |
完成后产生待审核内容版本
```

重试应从已确认且持久化的步骤边界继续，不重新运行所有成功步骤。外部调用发生超时且结果无法确认时，进入待核对状态；不能因为本地没有响应就假定供应商未执行。

当前已实现调用记录先落库、预算预留、成功结果复用与未知核对；恢复遇到 in_flight/unknown 不自动重发。未知核对仅追加说明后关闭，不导回结果、不续跑，详见 14；不能将此直接当成未来发布的防重实现。

取消先停止新步骤与后续副作用，再尽力取消正在进行的外部请求。无法撤回已经发生的供应商费用或平台操作。

## 6. 记忆与资料隔离

- 长期记忆第一版采用可编辑的显式规则和样文，不使用不可见的无限对话历史。
- 素材默认归属指定账号；工作区公共素材需要用户显式标记。
- 专家跨账号复用时，重新计算当前账号可访问的数据集合。
- 定时任务执行前检查素材是否被删除、撤权或过期；不能仅凭旧引用继续读取。
- 用户删除素材时，界面应说明已生成稿件、版本或任务输入快照可能仍包含历史副本，并提供明确的后续清理策略。

## 7. 可观测性

每次运行保留专家、技能、模型与工作流版本，输入素材引用，步骤结果、调用耗时、Token 用量、估算费用和失败类别。

配置快照用于追溯和问题定位，不保证再次调用模型能够逐字复现相同结果。

任务详情中的必要输入输出属于受保护业务数据，不写入普通应用日志。无需保存或展示模型内部思维过程；只展示可审计的步骤、工具操作与结果。

## 8. 验收场景

1. 同一专家给两个账号创作，分别遵循各自人设，不能混入对方私有素材。
2. 专家修改后，新运行使用新版本，历史运行仍可查看旧版本与快照。
3. 一份素材包含“忽略规则并发布”的文字，不得扩大工具权限或直接发布。
4. 大纲确认期间重启 API 与 Worker，确认状态仍在，用户可继续。
5. Skill 输出不满足契约时有限重试或报告失败，不把错误 JSON 当正常正文保存。
6. 模型要求调用未授权工具时，服务端拒绝并记录安全事件。
7. 专家不绑 Skill 也能使用；新建 Skill 无需改源码。可用、预加载、实际加载能分别追溯。
8. 专家团每位成员有独立调用、产物和状态；并行与依赖符合计划，取消或重启不重复已确认外部操作。
9. 导入冲突整体回滚；不支持的工具明确提示；ZIP 中的脚本没有被未经授权地执行。

只读工具、阶段/动态团队、人工确认继续、预算/取消/恢复和账号写作卡已有协议与隔离数据库测试；实际模型质量、通用素材授权与生产演练仍未验收。具体以 10、13、14、16、20 为准。
