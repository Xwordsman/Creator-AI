# 13 WorkBuddy 能力对齐计划与验收

> 更新：2026-11-02。产品决策：D-011。
> 用户已确认：完整对齐专家、Skills、专家团的功能，而不是只做几个提示词模板。
> 当前交付：能力配置/版本/包管理、模型适配、只读 Skill 工具、独立成员阶段执行、成功草稿分支修改与受限动态团队交互。C2/C3 部分完成，真实供应商质量、完整单专家会话与生产运行仍待验收，详见 14–16。

## 1. 什么叫“完整对齐”

Creator-AI 独立实现相同用途的能力，保留 Docker / Web 形态、账号人设与内容生产业务。对齐的是用户可完成的工作和运行语义，不是逐像素复制界面，也不是复制 WorkBuddy 私有代码、内置专家正文、提示模板、图标或商业服务。

基线来自本机 WorkBuddy 5.3.5 随附规范及静态代码线索，证据见 [历史核对](./12-workbuddy-alignment-review.md)。本轮补读 `expert-manager/references/team-spec.md`，确认主理人、独立成员、分发、消息与任务依赖的设计。**没有操作 WorkBuddy GUI、调用其模型或验证其真实团队运行；静态规格不是运行兼容证明。**

以下规则不可为了演示而省略：

- 单专家可以没有 Skill，也可以有自己的身份和口吻；具体账号表达要求优先。
- Skill 是 `SKILL.md` 加可选资料、模板和脚本的能力包，不是固定枚举。
- 可用、配置为预加载、实际加载指令、实际调用工具、结果通过验收是不同状态。
- 专家团有独立成员上下文、调用与结果；一个模型在一次调用里模拟多人对话不算完成。
- Docker 服务器没有浏览器所在电脑的天然桌面权限。桌面能力需要明确授权的连接器或本地桥接，不将未知工具静默替换成“已支持”。

## 3. 本轮交付的真实边界

### 专家与专家团

- 专家中心可创建单专家或专家团，可复制、搜索筛选、编辑为新版本、查看历史及停用。
- 一个团队保存 2–12 个成员，包含唯一主理人。成员有独立标识、指令、技能配置和最大轮次。
- 可将已有单专家的当前定义复制为成员；这是快照，不与来源专家保持动态关联。
- 可配置最多 20 个阶段，同阶段最多 3 位成员并行、阶段间串行，主理人最后独立汇总；固定阶段是 Creator-AI 的结构化扩展，不是自主拆解。
- 创建任务可另选受限动态模式：主理人提案，用户批准后派工，成员真实追问同伴或用户，反馈后重规划；等待/答复与派生任务持久化，串行执行且受硬上限和总预算约束，详见 [16](./16-dynamic-team-collaboration.md)。
- 自然语言 SOP 保留为指令，不自动变成经过授权的执行计划。阶段不能向主理人自己派工。

### Skills 与版本

- 原有三项内置定义保留只读；新增 `skills`、`skill_versions`，不再限制只能使用三个固定标识。
- 可保存 `SKILL.md`、查看附带资源、编辑指令并保留资源；“复制指令”不复制资源。
- 专家引用技能标识，**目前创建任务时解析当前版本**；固定版本、版本回退与包升级尚未完成。
- 任务保存完整技能定义与资源快照。配置变化不改写历史任务。
- 启停不增加内容版本；专家/Skill 停用不能用于新任务，不自动取消旧快照。模型连接每次发送前检查启用状态；没有通用工具撤权或素材授权系统。

### 运行提示

`RunSnapshot.skillSelection` 是配置和创建时事实，不改写历史。实际加载在 `execution.agents[].loadedSkillKeys`，实际版本来自 `snapshot.skills`，工具单独记录。mock 仍不加载、不推理；不回填伪造历史。

创作工作台默认 mock；选择已启用模型后可执行单专家/专家团。未选连接的团队仍由后端独立返回 422，不能降级为模拟多人。保存连接不自动调用收费 API。预算/取消/结果未知的完整约定见 [运行契约](./14-agent-runtime.md)。

成功稿可提交修改要求，复用其冻结的账号/专家/技能/模型配置和原运行模式，生成独立新分支；原稿与账本不变，真实模型每轮重新计费并使用独立预算。团队参与执行的成员独立获得来源正文与本轮要求，动态模式仍先规划/批准。修改分支不是在原任务里补问，只保留直接来源正文，不等于完整聊天记忆；失败/未知任务不能从该入口重发，详见 [15 草稿继续创作](./15-draft-continuation.md)。

## 4. 包格式与兼容性

支持两类受限 ZIP，允许一层外包装目录：

```text
standalone-skill/                  expert-package/
  SKILL.md                          .codebuddy-plugin/plugin.json
  references/                       agents/<agent-id>.md
  assets/                           skills/<skill-name>/SKILL.md
  scripts/                          skills/<skill-name>/references/
                                    settings.json  (team)
```

1. Skill 的 YAML 必须有 `name`、`description` 与非空正文；标识末段与 `name` 相同。不要求所有文本技能额外提供 JSON Schema。
2. 专家清单必须声明 `expertType`、入口 Agent 和包内资源；Agent `name` 对应文件名，禁止 Agent 声明 `tools`。
3. 团队 `teamInfo.memberAgents` 不含主理人；展示 `members` 包含主理人且其角色为 `lead`；`settings.json.agent` 指向主理人。
4. 专家包内技能按 `包名:技能名` 安装；目前拒绝不在包内提供的技能依赖，不会静默从服务器全局寻找替代项。
5. 原始文件内容存档，未知字段不授予权限。头像和私有工具资源可保存但未启用；含脚本时提示仅存档。文本与依赖语义没有完整静态分析，包内可能仍含不可执行的桌面/MCP 指令。
6. 导入先预览再确认；预览不写库。标识冲突返回 409，不覆盖用户现有技能；专家与全部新技能在同一事务安装。
7. “原始包”按存档文件重新打 ZIP，**不是原 ZIP 字节、目录记录和时间戳的完全复原**；有一层包装目录时保存规范化后的文件路径。普通导出按当前配置重新生成清单和 Agent，附带当前技能，不能保证保留未知清单字段的语义。
8. 再生成包使用 `expert-<id>` 命名空间，版本为 `1.0.<内部版本>`。相同本地技能名分配不冲突别名；不承诺导回后保留原技能 key 或可直接覆盖安装。
9. `creatorAi` 扩展保存团队阶段、团队指令、技能作用域和预加载配置。第三方产品可能忽略该扩展；本项目往返测试不代表 WorkBuddy 接受并等价执行。

资源限制：ZIP 最大 2 MiB、最多 128 个条目、单文件 512 KiB、累计解压 4 MiB；导出同样限制容量。仅内存解析，不解包至服务器目录。拒绝路径穿越、绝对路径、反斜杠、大小写/规范化重名、链接、加密包及超限内容；不自动展开嵌套 ZIP、不运行安装命令。

当前普通 JSON 上限 64 KiB；专家与技能配置路由单独允许 2 MiB，以容纳中文团队定义。字段长度、成员与技能数量还有各自约束。库总容量、版本保留和导入频率限制仍需补齐，不能据此宣传适合不可信多租户公网使用。

## 5. 必须完成的执行里程碑

以下按依赖顺序推进，不是“有空再做专家团”。也不承诺所有工作能在一个开发轮次完成。

### C1 能力目录与包管理（本轮部分完成）

本轮通过配置、版本、受限导入导出、安全校验、真实数据库及桌面/手机测试。剩余账号默认专家、引导创建、头像、试运行入口、版本固定/恢复、目录导入与包更新不能从完整目标中删除。

### C2 真实单专家与 Skill 执行（部分完成）

已实现加密连接、受控出站、先落库的调用/预算、只读 Skill 工具循环、取消/核对及成功稿分支修改；通过本地 HTTP 协议 fixture 与数据库测试。剩余真实服务商互通、人工质量验收、独立试运行、完整多轮聊天/交互确认和更完整授权资料链路。

- 建立加密模型连接、受控出站、能力检测、小额度连接测试。
- 先持久化 `ModelInvocation`、预算预留、结果未知与恢复策略，再开放付费调用。
- 实现 Agent 循环、轮次/时间/Token 限制，先提供只读 Skill 加载与包内资料工具。
- 每次加载和工具调用记录实际 Agent、Skill 版本、输入输出摘要、状态与产物引用。
- 账号上下文优先级、跨账号隔离、未授权工具拒绝、继续同一内容及取消必须实测。

**退出标准：**用户自建一个未写在源码中的 Skill，专家按需加载它并处理授权资料，记录能证明实际调用；无 Skill 的专家也能正常完成任务。模型结果需人工评价，不能只验证 HTTP 200。

### C3 真实专家团（部分完成，仍是必做）

已实现独立成员上下文/调用/结果、阶段依赖/并行、派工回报、主理人单独汇总、账本恢复及整团新一轮修改。另有显式动态模式：主理人模型提案、用户确认派工、成员追问/用户补问、拒绝后重规划及持久化等待/恢复，范围见 [16](./16-dynamic-team-collaboration.md)。固定阶段仍不冒称自主拆解；动态模式串行且有硬上限，成员异构模型、生产故障演练与真实质量仍待完成。

- 增加持久化团队运行、成员运行、任务依赖、消息与产物；成员使用独立上下文和模型调用。
- 主理人创建/拆分任务、向成员派发、接收回报或追问，保留成员原始产出后汇总。
- 从结构化阶段开始：同阶段并行，前置未完成不执行下一阶段；随后支持受控的动态派发与依赖调整。
- 展示团队总进度与每位成员的状态、技能加载、成本、结果及失败原因。
- 取消、成员失败、超时、重启恢复和未知调用不得导致无限派生任务或重复扣费。

**退出标准：**主编、资料员、主笔、审校有独立运行证据。并行资料任务确实并行；主笔等待资料，审校引用主笔产物，主理人汇总而非伪造成员发言。故障恢复不重跑已确认的外部调用。

### C4 完整体验与工具适配

补齐引导式专家制作、资料转专家、默认绑定、试运行、版本恢复/更新、分享发现和兼容性报告。按实际依赖加入沙箱、受控浏览器与文件工具；需要本地桌面的能力单独提供显式连接方案，不让服务器获得任意宿主访问权限。

C2/C3 与内容编辑审核、导出闭环衔接，定时任务与发布只能复用已经验收的运行语义，不能另写一套模拟团队逻辑。
