# 18 围绕文章的 AI 协作编辑

> 2026-11-09 · 0.0.1 开发预览。记录已实现的协作流程、数据与运行边界。测试证明编辑保护和执行协议，不代表文章质量已验收。

## 1. 体验与使用路径

`内容库 → 打开稿件 → 打开 AI 协作 → 讨论 / 累积批注 → 发送当前稿 → 查看建议对比 → 勾选采用 → 人工核对 → 保存新版本`

- 对话围绕编辑器里的当前标题和正文，包括未保存的编辑。发送不会保存稿件，也不会改变审核状态。
- “先讨论”只返回解释或问题；“给修改建议”返回可选择的局部修改，信息不足时也可以先提问。
- 在正文中点选一个段落或选中文字添加批注，也可以从段落列表选择，方便手机使用。支持整篇修改意见。
- 一次可累积最多 20 条“修改”或“保留”批注。“保留”优先；只有段落修改批注时，其他段落和标题不能修改。
- 查看每条建议的原文、建议稿和原因，只应用勾选项。应用后仍是本地编辑，必须显式“保存新版本”。
- 提供一次 AI 采用操作的撤销。采用后若又编辑了标题或正文，拒绝直接撤销覆盖，需自行核对或使用编辑器撤销/版本历史。
- 对话按文章持久保存；未发送要求、批注、未加入清单的意见以及未确认请求保存在按用户/文章隔离的 `sessionStorage`。本地恢复不是跨设备备份。

## 2. 模型、专家和上下文

每轮显式选择可用模型，空选项为“本地模拟 · 不调用 AI”。模型列表不可用或所选连接失效时，不自动切换到其他收费模型。模拟只返回明确标注的流程回复，不理解正文、不生成改写建议。

默认沿用文章原始来源任务的账号人设、专家方法和技能/资源快照。现可显式选择本轮使用账号当前资料，以 `accountProfileRevision` 确认准确修订并冻结；资料变化则拒绝新建，不自动追随新版。专家与技能仍沿用原稿。选择、资料快照和未知重试规则详见 [20 账号写作资料](./20-account-writing-cards.md)。创建前重新检查原账号、专家、技能和所选模型的可用性；专家团在这个入口只使用负责人独立协助，尚不启动完整专家团。

上下文包含当前完整稿、当轮要求和批注，另带最近最多 6 轮成功的真实交流，用户要求与回复合计最多 12,000 字符。历史超限会截断并提示。旧回复不是已接受的稿件，当前稿始终是原文基线；没有永久记忆、自动学习或模型训练。

复用只读 `load_skill` / `read_skill_file` 工具、调用账本与预算。每轮独立上限为 4 次调用、64,000 tokens、180 秒，仍受模型输入/输出和专家轮次限制；这不是金额上限，工具循环可能产生多次调用。长文可能超过连接的输入限制，不能保证所有兼容服务商均能返回符合协议的建议。

## 3. 建议协议和编辑保护

模型必须返回严格 JSON：`reply` 与 `suggestions`。每条建议包含唯一标识、目标段落索引、完整 `before` / `after`、理由及关联批注标识。`blockIndex=null` 只代表文章标题。

- 讨论模式必须没有建议；每轮最多 20 条，同一目标最多一条。
- `before` 必须逐字匹配发送时的完整段落或标题。引用的批注必须存在，不能修改“保留”段落或越出限定范围。
- 当前只替换已有段落的纯文本，不增加、合并、移动或删除段落；普通段落可清空，小标题不可清空。沿用正文白名单和总量限制。
- 服务端和应用前都校验建议。非法输出记为 `ASSISTANCE_INVALID_OUTPUT`，停止本轮，不自动发起收费纠错。
- 应用前核对当前本地标题/正文及基础修订与发送快照一致，并重新读取服务器修订。任何一处变化都不能直接采用旧建议。
- 应用仍不写服务器。后续保存沿用内容模块的行锁、修订校验与幂等收据，因此应用后发生的服务器并发更新仍会在保存时被拦住。
- 建议只能从对应文章采用。协作任务不能再次“加入内容库”或走候选稿“继续创作”，避免把回复当成新文章。

提示词要求保留作者真实表达，不以虚构故事、来源或口头禅制造“人味”；技术校验不能保证模型忠实、文风合适或事实准确，这些仍需人工阅读评价。

## 4. 持久化、重试和未知结果

新增 `ContentAssistance1794096000000` 迁移，仅新增 `content_turns`：任务主键、文章引用、基础版本与历史索引。正文/要求/批注保存于不可变任务快照，结果保存于任务输出；不修改历史内容版本。`down` 拒绝删除对话和计费证据。

创建使用内容行锁，任务、关联及 Outbox 同事务提交。一篇文章最多存在一轮排队、运行、等待或待核对的协作任务。同 owner 的创作幂等键空间复用，输入摘要包含操作与文章；先回放准确旧任务，再检查修订，防止收到请求后网络断开导致重复调用。

浏览器发送前保存准确稿件快照、要求和幂等键。网络/5xx/408/429、畸形 4xx 与无效成功收据等不明确结果保留原请求，刷新后只提供显式“原样重试 AI 请求”，不自动发送。重试不会使用后来编辑的正文。先校验任务/文章身份、基础修订和模式，再清除待确认记录。存储不可用时不发新请求；损坏的待确认记录（包括存入的 JSON null/false）会阻止新提交，要求先核对。

后台沿用运行租约、调用账本、取消与未知结果核对。`needs_review` 阻止该文章新一轮，入口链接到任务记录；核对后保留调用与预算证据，不自动重发或续跑。取消是尽力停止后续调用，不保证请求未收费。浏览器离开后迟到响应不能改写新页面，收起协作停止浏览器轮询，后台任务仍继续。

## 5. HTTP 接口

继承认证、owner、Origin/CSRF；文章路由 JSON 上限 2 MiB，统一响应 envelope。

| 接口（`/api/v1` 前缀）                      | 输入 / 返回                                                                                               |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| POST `/contents/:id/assistant-turns`        | `baseRevision,title,document,mode,message,annotations,modelConnectionId?`，幂等键必填，202 返回任务元数据 |
| GET `/contents/:id/assistant-turns`         | 分页元数据与回复/建议；未传 pageSize 时返回最多 20 条，显式传入也限制为 20，不批量携带原文或递归历史      |
| GET `/contents/:id/assistant-turns/:turnId` | 本轮元数据、结果和用于采用校验的准确原稿快照                                                              |
| POST `/creation-runs/:id/cancel`            | 复用任务取消                                                                                              |
| POST `/creation-runs/:id/reconcile`         | 复用未知调用人工核对                                                                                      |

页面每页 10 条，活动任务约 2 秒刷新一次；刷新或重新打开可读取已持久保存的对话。查看旧页时另核对最新任务，不能绕过单篇并发限制。

## 6. 验证与后续

本轮共享契约测试覆盖锚点、保留优先、范围、JSONB 语义比较、白名单、标题和选择采用；新增 11 项真实 PostgreSQL/本地 HTTP 协议集成测试，覆盖事务幂等、并发、归属/CSRF、历史边界、非法输出、不确定调用、模拟真实性与配置冻结。

新增 20 项桌面/手机 Playwright 测试覆盖未保存稿、多批注、部分采用、撤销/保存、旧建议失效、批注刷新恢复、未知 POST 原样重试、轮询/核对入口、编辑器锚点、取消与迟到响应。完整套件的最新结果见 [10 实施状态](./10-implementation-status.md)。协议 fixture 不请求付费模型，不评价写作质量。

下一步需要用家人的真实人物卡、写作卡、原文与人工修改样例评价：哪些表达应该保留、哪些 AI 习惯需要避免、不同模型的建议是否有效。尚未实现文章配图/封面模型、图片管理与排版、跨文章长期偏好、独立聊天产品或自动发布；这些不属于当前协作编辑已交付范围。
