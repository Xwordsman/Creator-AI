# 20 账号写作资料

> 2026-11-09。已有 Markdown 人物卡、写作卡和范文的复用入口。资料组织与上下文接入不等于模型质量验收。

## 1. 使用流程

1. 在“账号档案”打开对应账号的“写作资料”。可多选导入 UTF-8 `.md` / `.txt`，也可手动添加。
2. 检查分类、名称和正文；文件名只用于初步分类，可自行调整。每份资料可启用或停用，点击“保存写作资料”才写入服务器。
3. 新创作读取已保存的账号资料，工作台可展开核对。创建时冻结资料全文、启停状态和账号修订；任务详情展示实际快照。
4. 已有文章打开 AI 协作，默认“沿用原稿资料”。如需新资料，明确选择“使用账号当前资料 · rN”；发送前仍可展开核对。
5. 资料只参与本轮背景。模型给出局部建议后，仍由作者勾选采用并显式保存正文；保存资料本身不调用模型、不改文章。

| 分类   | 用途                             | 边界                                         |
| ------ | -------------------------------- | -------------------------------------------- |
| 人物卡 | 身份视角、表达边界和作者习惯     | 不清楚的身份事实需要向作者确认               |
| 写作卡 | 开头、结构、用词和禁忌等写法约定 | 本轮明确要求优先，不授予工具权限             |
| 范文   | 参考节奏、结构与语气             | 不照抄，不把范文经历、关系或数据作为作者事实 |

卡片是账号背景，与专家的工作方法和 Skill 能力包分别管理。无须给每张卡创建专家或改成 SKILL.md。模型提示词明确三类语义；这不保证模型必然遵循，仍需人工评价。

## 2. 导入与容量

- 每账号最多 8 份；单份标题 1–80 字符，正文 1–8,000 字符，所有卡片正文合计最多 24,000 字符。停用卡片也计入存储限制。
- 每文件最多 64 KiB，仅 UTF-8；拒绝非法编码、空白正文及非制表/换行的 ASCII 控制字符。多文件全部读取和校验成功后才加入本地编辑，失败不部分导入。
- 保留正文 Markdown 和普通换行。资料以纯文本编辑、预览并进入模型上下文，不渲染 HTML，不执行代码、不抓取链接、不自动读取关联文件。
- 每张卡有稳定 UUID，单账号不可重复。没有压缩包、图片、PDF、Word 导入，也没有检索、向量库或自动提炼。
- 界面编辑是窗口内暂存，关闭后未保存编辑会丢失。卡片可能随任务快照留存，后续移除或停用不删除历史任务副本。

资料会随文章内容发送给用户选择的文字模型。停用卡片保存在账号和任务配置快照中，但不发送给模型；任务详情的默认资料预览仅列出启用卡片。

## 3. 修订、冻结与恢复

资料存于现有 `accounts.profile.writingCards` JSONB 可选字段，不新增迁移、不回填旧账号、不改历史任务。旧账号和任务缺少此字段时按无卡片处理。资料修订与默认专家共用 `accounts.revision`。

保存使用账号行锁和 `baseRevision` 乐观并发检查；成功递增一次修订。并发修改返回 `409 ACCOUNT_REVISION_CONFLICT`。本接口不创建收费任务，没有持久化幂等收据；网络或服务器异常后界面冻结再次写入，要求先读回服务器资料。作者可逐份展开核对，再选择采用服务器资料，或保留本地内容、以刚读取的修订重新确认保存。不会自动覆盖或静默合并。

新任务自动冻结当时资料，草稿分支继续沿用来源快照。已有文章协作默认沿用最初来源账号；选择当前资料时提交精确的 `accountProfileRevision`，事务内持有账号读锁、检查修订后冻结。期间有新修改则拒绝创建任务，作者需刷新、重新选择，不自动把选择切到新版。

协作快照另存 `writingProfile`：来源 original/current、账号修订和启用卡片的 ID/类别/标题，历史列表显示本轮实际选择。卡片全文只保存在受保护的任务快照中，不重复塞进历史列表。切换账号资料不切换来源专家和技能；专家团仍只由原负责人编辑。

早期账号快照可能没有修订号，接口保留原样，界面显示“未记录修订”；基于该快照的新协作收据记 `accountRevision: null`，不猜测版本、不回填旧任务。当前账号选版仍必须提交实际的正整数修订。

协作原有幂等规则继续适用：请求摘要包含所选资料修订，先回放准确任务，再检查当前配置。发送结果未知时，原稿、要求、资料选择和键一并冻结；账号随后改变也不能让原样重试变成另一次调用。旧版 sessionStorage 草稿保持兼容，缺少选择字段表示沿用原稿。

## 4. 接口

均带 `/api/v1` 前缀，继承会话、归属和 Origin/CSRF 校验。

| 接口                                                | 输入 / 返回                                             |
| --------------------------------------------------- | ------------------------------------------------------- |
| GET `/accounts/:id`                                 | 当前账号与资料，owner 隔离                              |
| POST `/accounts/:id/writing-cards`                  | `{baseRevision,writingCards}`，200 返回更新账号         |
| GET `/contents/:id/assistant-turns/writing-profile` | `{original,current}`，原稿冻结账号和当前账号            |
| POST `/contents/:id/assistant-turns`                | 原协作输入加可选 `accountProfileRevision`；未传沿用原稿 |

账号 JSON 路由上限调整为 2 MiB，内容仍受更小的契约容量约束，避免 24,000 中文字符合法资料被原 64 KiB 解析限制拒绝。普通非配置请求仍为 64 KiB。模型输入限制及单轮预算继续独立生效，资料过长可能超出所选模型上限。

## 5. 验证边界与后续

自动化覆盖编码/大小/原文保留、显式保存、失败批次原子性、并发修订、归属与 CSRF、旧任务冻结、分支复用、停用过滤、协作显式选择及过期拒绝、未知结果同键恢复。模型路径使用隔离数据库和本地 HTTP 协议 fixture；不调用收费服务商。

本轮没有把家庭真实卡片写进预览业务数据，也没有对实际文章质量作通过结论。下一步应由作者挑选少量真实卡片和一篇文章，使用已确认的文字模型，评价“原稿资料 / 新资料”对具体改稿的影响，再决定卡片精简、冲突提示和图片创作需求。
