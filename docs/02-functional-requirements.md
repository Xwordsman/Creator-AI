# 02 功能需求

## 1. 范围与编号

需求编号用于关联设计、实现和测试。标注“v0.1”的能力属于第一版范围；“后续”能力不得阻塞基础创作闭环。

建议一级导航：工作台、账号、专家中心、技能库、素材、内容、计划、发布、设置。Skills 是独立能力库，可被单专家和专家团成员复用。人设主要在账号中编辑；专家也可有默认身份与口吻，账号表达要求优先。发布入口在第一版只展示导出与真实支持的能力。

D-011 将完整专家/Skills/专家团对齐确认为产品目标；当前完成与待做项见 [能力对齐计划](./13-workbuddy-capability-plan.md)，不得把目标清单当作已实现清单。

账号列表与内容列表应提供必要的搜索、筛选和分页，不为第一版引入复杂自定义报表或仪表盘编辑器。

## 3. 专家与技能默认模板

建议首批模板：公众号主笔、选题编辑、文章审校、口播脚本编导。模板只是可修改的预配置，不代表多个专家会自动组成团队。专家团必须显式组建：例如“主编 + 资料员 + 主笔 + 审校”，配置任务与依赖；执行器未接入时标为仅配置，不允许提交团队任务。

建议固定流程：

1. 原创文章：主题 -> 大纲 -> 正文 -> 疑点检查 -> 排版草稿。
2. 素材成稿：选定素材 -> 提炼观点 -> 大纲 -> 正文 -> 检查。
3. 选题建议：账号定位与素材 -> 候选选题 -> 人工确认入队。
4. 文本改编：已有内容 -> 目标账号要求 -> 新草稿或口播稿。

分步确认是可选配置。定时成稿默认采用“已确认选题 -> 完整草稿 -> 人工审核”；如果用户选择中途确认，任务应明确进入待确认状态。

## 4. 核心页面交互

### 4.1 创作页

至少包含账号、单专家或专家团、主题、流程、选定素材和补充要求。目标是从账号带入默认值，但用户能看到实际选择，而不是黑盒决定。当前账号默认专家尚未实现；工作台选择首个启用单专家，不能宣传为智能推荐或记忆。

提交前显示本次可用工具、是否会发送资料到云端模型、预算限制。提交后展示步骤与结果，支持离开页面后再回来查看。

### 4.2 专家配置页

分区组织职责与指令、Skills、参考资料、模型、工具权限和测试。基础用户不需要了解底层消息角色或编排代码即可使用。

试运行必须显式选择测试账号或沙盒上下文，遵守相同的数据隔离、调用预算和工具权限；不能以测试名义发布内容。

团队编辑器独立配置主理人、成员角色、可用技能和预加载、协作 SOP、依赖阶段。复制已有专家为成员时说明是快照，不因修改来源专家而悄悄改变团队。

技能库提供独立管理与资源预览。ZIP 先预览，再由用户确认保存；显示解析警告与运行支持程度。“导入成功”不能显示为“执行就绪”。

### 4.3 内容编辑页

编辑区与版本、素材来源、生成记录、审核状态联动。生成中的文本先作为候选结果展示，不连续覆盖用户正在编辑的正文。

审核通过后再保存修改，需要清除新版本的审核状态并提示用户。文件导出不等于平台发布成功。

### 4.4 计划页

明确显示计划时区、下次预计执行时间、候选选题数量、每次篇数、并发限制和预算。默认停机漏跑策略为跳过历史时点、不集中补跑。

一期站内提醒覆盖待审、待确认、失败、额度不足和选题不足。邮件、Webhook 等外部渠道作为后续能力，不能在未配置时假装已通知到外部。

## 6. 通用质量要求

- 所有表单有校验、加载、空态与失败反馈；失败信息可操作，不只显示“系统异常”。
- 桌面端优先优化创作效率，移动端至少可查看进度、审核和轻量编辑；不承诺完整移动剪辑能力。
- 生成结果中的事实和引用需可回查；没有来源则标记待核实，不虚构引用。
- 用户素材中的文字属于数据，不能改变系统权限或触发未经授权的工具。
- 模型请求超时、取消或服务重启可能发生费用，界面需要明确区分本地状态与供应商状态。
- 第一版不实现复杂 RBAC，但每个 API、SSE、文件下载和后台动作均要校验数据归属与必要权限。
