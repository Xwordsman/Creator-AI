# 19 模型连接检查

> 更新：2026-11-09。用于接入真实文字模型前检查基础协议；不是写作质量评分或完整能力探测。

## 操作路径

1. 部署者按 [14 运行契约](./14-agent-runtime.md) 配置真实模型模式、稳定的加密主密钥与精确出站白名单。
2. 在「模型设置」保存连接。保存、启用连接及打开「检查连接 / 记录」只处理配置或读取记录，不调用模型。
3. 勾选费用确认，点击「发送一次检查」。服务端使用保存的模型标识、Token 参数和凭证发送一组固定短文本，要求仅回复 `{"ok":true}`。
4. 基础协议通过后，在工作台试写，或在文章编辑台打开 AI 协作，选择该连接讨论或获取修改建议。最终仍需人工评价文风、事实与修改质量。

检查不发送文章、人设、专家指令、Skills、文件或历史聊天，不开放工具。每次新检查最多调用一次模型，最大输出 256 Token，可能收费；不会为了修正 JSON 再付费调用。256 Token 是输出请求上限，不是费用硬上限；服务商可能将推理消耗计入额度，导致某些模型无法在此上限内交付有效回复。

## 结果与处理

| 状态      | 含义                                                                   | 下一步                                                                |
| --------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `running` | 已保存检查意图，正在准备或等待回复                                     | 窗口打开时约每 2 秒读取记录；等待，不创建重复检查                     |
| `passed`  | 接口返回完整的兼容文本响应，正文是要求的 JSON                          | 可以试写；不表示已验证工具、长文、图片或全部模型能力                  |
| `failed`  | 发送前失败、服务商明确拒绝，或完整回复不符合固定 JSON                  | 按提示核对地址、模型、密钥、权限或输出参数；已响应的请求仍可能收费    |
| `unknown` | 已标记发送，但超时、断线、回复损坏、进程中断或服务商异常导致结果不确定 | 先核对服务商记录，再保存 10–2000 字说明；系统保留未知证据，不自动重发 |

401 提示密钥无效；403 提示权限/额度限制；404 提示地址或模型不存在；429 提示频率/额度。只保存分类码，不复制服务商错误原文或原始回复，避免将敏感信息带入浏览器和日志。未提供 usage 显示「未提供」，不显示成零费用。检查中断也不能据此断言未扣费。

人工核对保留原 `unknown` 状态，追加时间与不可覆盖的说明，之后才允许发送新的检查。相同说明重复提交返回原记录，改变已保存说明返回 409。这不代表系统确认了账单、不退款、不导入回复，也不恢复旧请求。

## 持久化与断线语义

- 检查使用独立 `model_checks` 表，不建立文章、专家、创作任务、Agent、Outbox 或工具执行记录；不占某篇文章的调用预算，也没有跨任务费用总额控制。
- 创建时先事务提交意图，再条件更新发送标记，然后请求服务商。同 owner、同幂等键始终回放原记录，不重新发送；键跨模型复用返回 409。
- 每个连接同时只允许一条运行中或尚未核对的未知检查，由数据库锁和唯一约束保护。它不阻止该连接的其他创作任务，不是全局模型额度锁。
- API 直接执行检查，不依赖 Worker。发送使用 20 秒 AbortSignal；记录 90 秒到期。读取历史或回放请求时处理过期记录：未标记发送的转为失败，已标记发送的转为未知。迟到回复不能覆盖到期状态。
- 浏览器把未确认的请求键按用户/连接保存在当前标签页 sessionStorage。刷新或重新打开窗口不会自动 POST；用户可「原样重试检查请求」查询或补交，保留同键和确认输入。如果原请求根本未到达服务器，补交会发送首次调用；已存在的请求只返回记录。
- 关闭窗口停止读取轮询，不取消已开始的调用。浏览器存储不可用时停止新检查，避免丢失请求标识。标签页关闭或存储清理会丢失本地标识，仍应先查看服务端记录。
- 最近记录最多显示 10 条；已持久化的幂等回放不受这 10 条显示限制。模型连接目前不能编辑或轮换密钥，见 14 的限制。

## HTTP 契约

路径以 `/api/v1` 为前缀，均验证会话与 owner，POST 另验证精确 Origin 和 CSRF。成功套 `{data,requestId}`；调用结果未知也返回持久化记录，不用一个泛化网络错误代替证据。

| 方法与路径                                   | 输入与返回                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| GET `/models/:id/checks`                     | 最近 10 条检查数组，仅当前连接所有者可读；不发模型请求                                                          |
| POST `/models/:id/checks`                    | 严格 `{confirm:true}`，必需 `Idempotency-Key`（16–128 位字母、数字、下划线或短横线）；返回 200 检查记录或原记录 |
| POST `/models/:id/checks/:checkId/reconcile` | `{note}`，trim 后 10–2000 字；返回 200 已保存核对记录                                                           |

记录包含检查 ID、连接 ID、状态、分类码、服务商报告的输入/输出 Token、创建/结束/核对时间及说明。不返回 API Key、加密凭证或原始回复。外部请求以检查 ID 作为 `X-Client-Request-Id`；服务商是否记录或支持按此查询，需自行核验，系统没有供应商自动查询适配器。

## 部署与验证边界

新增迁移 `1794182400000-model-checks.ts` 只创建检查表和索引，不改写旧内容；拒绝破坏性 down。升级前等待在途任务与检查结束，备份数据库和主密钥，再运行迁移。

API 因连接检查与 Worker 一起连接 `model_egress`；数据库和 Redis 仍只在内部网络，只有 gateway 发布端口。应用保持 HTTPS 白名单、全部 DNS 地址检查、socket 绑定及不跟随重定向。出站网络不是防火墙白名单；隔离 Docker 冒烟对 API/Worker 都覆盖为仅 `private` 并强制 mock。尚未完成实际 Docker 运行验收。
