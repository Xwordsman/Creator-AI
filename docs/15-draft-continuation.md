# 15 围绕同一草稿继续创作

> 更新：2026-11-02。当前是不可变候选稿的分支修改，不是完整聊天、编辑审核或失败任务续跑。沿用 14 的预算、权限与未知结果边界。

## 1. 用户路径

1. 在创作记录打开已成功生成的候选稿。
2. 在「围绕这篇，继续创作」填写 2–2000 字修改要求，不必重新输入账号人设、专家或 Skills。
3. mock 只验证上下文持久化，不理解或改写原稿。真实模型按钮明确提示新调用、可能的新费用和本轮独立预算。
4. 提交后创建新的后台任务，离开页面不取消执行；原稿、原账本不变。
5. 在「原稿与修改分支」查看同主题历史、任务状态和修改要求，返回来源稿或最初原稿。

同一来源可产生多个分支，不维护隐式“最新版”。深度 1 表示直接修改初稿，深度 2 表示修改其中一份修改稿；兄弟分支可以有相同深度。没有自动采纳、人工审核、发布版本或正文差异比较。每个分支最多 100 层。

## 2. 冻结和校验

- 来源必须属于当前 owner、状态为 `succeeded` 且正文通过有界 `runOutputSchema` 校验。运行中、失败、取消和 `needs_review` 均返回 `409 DRAFT_NOT_READY`，即使有部分成员结果也不能从此入口继续调用。
- 复用来源快照中的账号、专家/团队、技能指令/资源/版本、模型非敏感配置和预算。不自动切换到后来编辑的人设、专家或技能版本；要采用最新配置，从工作台创建新任务。
- 创建前重新校验原账号/专家归属及存在、专家和关联技能可用、模型连接存在且启用，并检查模型地址。停用后不能创建新分支；不因此修改或取消之前已保存的分支。模型仍在每次实际发送前重新检查启用和网络安全。
- 不允许提交者替换来源正文、owner、账号、专家、模型或预算。模型连接沿用来源；mock 绝不隐式升级成收费调用。
- 新任务的调用次数、Token 预留/用量、时间窗口、领取次数、取消状态、成员与工具账本重新开始。预算限额复用原值，但不是原任务的余额，也不是跨任务金额上限。
- `skillSelection.loaded` 在新快照中为空；实际 Skill 加载仍以新任务的执行证据为准，不复用原任务的加载声明。

## 3. 模型上下文

在原主题、原 brief、账号与专家方法之外，为每位独立成员提供：

- `revisionRequest`：本轮明确的用户修改要求；
- `previousDraft`：直接来源任务的完整候选输出；
- 该成员的当前分工与本轮依赖结果。

系统要求保留未要求改变的有效内容，主笔/主理人交付完整新稿，而不是只有修改清单。原稿和成员交付是不可信材料，不是系统权限或工具授权。每位成员仍独立调用；阶段和主理人规则不变，不伪装为动态追问。

仅复制直接来源的正文，不递归嵌入其上下文、前几轮修改要求、历史消息或账本。因此上下文不会随深度递归膨胀，但**不承诺完整对话记忆**。较早要求若不体现在直接来源正文中，需在当前要求中再次说明。正文超出模型输入上限时明确失败，不静默截断、不自动换大模型。

## 4. HTTP 与数据

`POST /api/v1/creation-runs/:id/continue`

```json
{ "instruction": "保留主要观点，把开头改得更直接，删除没有来源的数据。" }
```

需会话、Origin、CSRF 和 16–128 位 `Idempotency-Key`；202 返回完整 `CreationRun`。新建和继续共用同 owner 的幂等命名空间；摘要包含操作类型、来源 ID 和规范化要求。相同键/输入返回原任务，不再入队；不同输入或来源返回 409；事务锁保证并发请求只产生一个 Run/Outbox。返回既有任务不是重新执行，即使原配置后来停用也能返回原有证据。

`GET /api/v1/creation-runs/:id/history?page=1&pageSize=10`

返回标准分页，同 owner、同 root 的扁平分支元数据：`id/status/createdAt/lineage?/instruction`。按创建时间倒序、ID 稳定排序；不批量返回历史正文、模型凭证或执行账本。历史状态随任务执行变化，页面可主动刷新。来源不可见返回 404。

新分支 DTO 的 `lineage` 包含 `parentRunId/rootRunId/depth`；`snapshot.continuation` 另存 `instruction/previousOutput`。最初原稿不补写历史快照或 lineage。增量迁移 `1793750400000-draft-continuation.ts` 仅新增父/根 FK、深度、约束和 owner/root 时间索引；拒绝破坏性 down，没有新增独立 Content 实体。

## 5. 前端提交安全

提交只由用户操作触发，不自动重试。当前标签页的 sessionStorage 按 owner/来源保存修改要求和幂等键；相同规范化要求在刷新或网络错误后重试仍使用原键。修改要求变化才换键。字段提交中不可编辑；返回原稿时仍可找回要求。键不跨标签页/设备共享，清理浏览器数据后也不可保证复用；重复操作前应先查创作记录。

存储不可用时页面提示风险；请求不明确时保留输入并建议查记录，不声称未创建任务。组件离开后，迟到的响应不得把用户导航回旧任务。页面显示新费用提醒，但不进行自动服务商测试或授权新的工具。

## 6. 验证边界

契约测试覆盖要求长度和未知配置字段；真实 PostgreSQL/Redis/本地 HTTP fixture 覆盖幂等并发、原稿不变、冻结版本/停用、owner、分支历史、状态门禁、独立预算与每位团队成员的修改上下文；桌面/手机浏览器覆盖修改、返回来源、刷新后幂等重试和迟到响应。

这些测试不是付费模型文章质量、完整对话体验、第三方 WorkBuddy 运行兼容、Docker 启动或备份恢复验收。实际运行结果见 10。后续仍需动态派发/追问、交互确认、编辑审核与导出。
