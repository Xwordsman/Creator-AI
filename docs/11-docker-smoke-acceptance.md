# 11 Docker 隔离验收

> 当前状态：验收工具已编写，工具单元测试与缺少 Docker 时的预检退出已在本机验证；尚未在 Docker 引擎上执行成功。本文不是部署通过报告。

## 1. 用途与前置条件

这条验收路径用真实应用镜像、PostgreSQL、Redis 和 Caddy 检查 0.0.1 模拟创作切片。它不使用浏览器测试的 API fixtures，也不调用真实模型或发布平台。

运行要求：

- Node.js 24.22.2；使用 pnpm 命令时需 pnpm 11.25.0。
- 本机可用的 Docker Linux 容器引擎；Windows 可使用已配置好 Linux 后端的 Docker Desktop。
- Docker Compose 至少 2.24.4，支持 `!override`，以彻底替换正式网关的端口配置。
- 当前 Docker endpoint 必须是本地 Unix socket 或 Windows named pipe；SSH/TCP endpoint 会被拒绝，不会切换 Docker context。
- 能拉取基础镜像、访问 npm registry，并有足够的构建磁盘空间。镜像标签仍需按实施状态文档核验维护状态。

脚本不会安装 Docker、WSL、Node 或操作系统服务，不会连接未明确指定的服务器。常规产品部署本身不要求主机安装 Node；Node 是这条开发验收命令的执行环境。

## 2. 执行命令

在仓库根目录运行：

```sh
pnpm test:docker
```

也可以直接执行，不需要安装主机上的 npm 依赖：

```sh
node scripts/docker-smoke.mjs
```

命令会构建真实镜像，首次运行可能需要数分钟。只有完整检查和清理都成功时才输出 `PASS` 并返回退出码 0；缺少 Docker、配置不满足隔离条件或任何断言失败均返回非零。

这不是长期运行的预览环境。测试完成后，临时管理员、测试数据与测试容器会一并清理；要保留自己的创作数据，请使用仓库 README 的常规部署流程。

## 3. 隔离与清理规则

- 每次生成新的 `creator-ai-smoke-<随机标识>` 项目名、独立应用镜像标签和临时随机口令；运行前检查同名容器、卷、网络和镜像不存在。
- 显式传入一个临时空环境文件，不读取仓库 `.env`，不复用正式管理员或模型凭证。口令通过进程环境传递，不放进命令行参数；Docker 管理权限仍可以读取容器环境，因此这不等于秘密管理服务。
- 网关仅绑定 `127.0.0.1` 上的临时端口；API、Worker、PostgreSQL、Redis 不发布端口。应用继续使用内部网络和 mock 模式。
- 执行前解析 `docker compose config --format json`，检查项目名、镜像、卷、网络、挂载和端口；拒绝外部卷、固定容器名、主机挂载、公开数据库端口等配置。
- 无论检查成功还是失败，都尝试清理本次项目的容器、网络、数据卷及两个测试应用镜像标签。**这些卷只承载本次生成的测试数据；不要手工替换成正式卷。** 不运行全局 prune，不删除基础镜像和构建缓存。
- 失败时输出有界日志，并遮罩本次已知口令和会话值。强制结束进程、机器掉电或 Docker 引擎失联仍可能留下资源；清理失败时会输出项目名，不会转而尝试清理其他项目。

若有残留，先按输出的项目名查看 Docker 资源标签 `com.docker.compose.project` 和资源名称，确认确实属于本次测试后再人工处理。不要用清空所有 Docker 卷来解决验收问题。

`compose.smoke.yaml` 仅供脚本与基础 Compose 合并使用，不要把它当作正式部署配置单独启动。

## 4. 验收覆盖

| 阶段 | 检查内容                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------- |
| 引导 | 构建生产镜像；等待数据库与 Redis 就绪；显式迁移；重复迁移无新增；首次管理员创建成功、再次引导被拒绝     |
| 入口 | Caddy 返回构建后的页面与脚本资源、安全响应头；API 就绪检查经网关返回 mock 状态                          |
| 认证 | 未登录请求被拒绝；登录取得 HttpOnly / SameSite Cookie；错误 Origin 和缺少 CSRF 被拒绝；注销撤销会话     |
| 创作 | 通过真实 HTTP 创建账号与专家；并发幂等提交只产生同一个任务；相同键不同输入返回 409；Worker 生成模拟结果 |
| SSE  | 经 Caddy 消费真实 `run.snapshot`，等待终态；处理跨数据块的消息、心跳、连接超时与错误事件                |
| 版本 | 专家更新为新版本；旧版本更新冲突；旧任务保留原专家快照                                                  |
| 重建 | 停止 Worker 后提交排队任务；保留卷重建数据库、Redis、API；原会话、账号、专家、草稿和排队任务仍可读取    |
| 恢复 | 重建并启动 Worker；排队任务完成且只领取一次；最后清理本次项目                                           |

这是容器重建与持久化冒烟验收，不是备份恢复演练。没有覆盖机器重启、生产域名/TLS、磁盘不足、网络分区、数据库升级回退、真实模型扣费或外部发布；也没有用浏览器验证正式容器中的全部交互。

## 5. 与其他测试的关系

- `pnpm test:tools`：19 项验收工具测试，检查隔离规则、进程超时/取消、日志遮罩、HTTP 与 SSE 解析；不需要 Docker，不证明应用容器能运行。
- `pnpm test`：执行工具测试及原有 contracts、后端和前端单元测试。
- `pnpm test:integration`：已有 PostgreSQL/Redis 集成套件，依赖专用 `_test` 数据库与 Redis DB 15；与 Docker 冒烟测试互补，并非由冒烟命令隐式运行。
- `pnpm test:e2e`：浏览器交互和布局测试，目前仍使用 API fixtures。
- `pnpm test:docker`：本文件描述的真实容器验收；本机当前无 Docker，仍未执行完整流程。

CI 已从只检查 Compose 配置和构建镜像，改为调用同一条 Docker 冒烟命令。CI 配置尚无远程执行结果；发布前必须查看并解决实际失败，不能仅凭工作流文件存在就勾选部署验收。
