# 14 模型、Agent 与专家团运行契约

> 更新：2026-11-09。本文记录已实现的执行子集，不代表 WorkBuddy 全量功能对齐、供应商互通或生产验收完成。

## 1. 启用与体验路径

默认 `MODEL_MODE=mock`，不请求外部模型，单专家可免费验证工作流。专家团不能走 mock，必须显式选择已启用的模型连接。

管理员启用真实调用时，在服务器环境设置：

```dotenv
MODEL_MODE=configured
MODEL_ENCRYPTION_KEY=<64 hexadecimal characters>
MODEL_ALLOWED_HOSTS=api.example.com
```

主密钥可通过 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成，稳定保存并单独备份；不能每次重建容器重新生成。API 与 Worker 必须使用同一主密钥和白名单。不要把真实值写入 Git、命令参数或公开日志。

白名单是逗号分隔的精确 `host[:port]`，不是 URL、不支持通配符。连接地址只能使用 HTTPS，不能携带用户信息、查询或片段；任何 DNS 结果为内网/保留地址均拒绝。生产环境不支持内网模型。仅非生产测试可显式设置 `MODEL_ALLOW_LOCAL=true`，允许白名单中的字面环回 HTTP 地址；Compose 不提供这个开关。

重新创建 API/Worker 后，进入「模型设置」，填写名称、Base URL、模型标识和 API Key，选择 Token 参数与输入/输出上限。Base URL 应是 API 根路径（例如 `https://api.example.com/v1`），系统追加 `/chat/completions`。保存或启用连接不会自动发起收费测试。可显式确认费用后检查基础文本/JSON 协议，固定短文本、最多一次请求、256 Token 输出上限；独立检查记录、幂等与未知核对见 [19 连接检查](./19-model-connection-checks.md)。没有自动能力探测，检查通过不证明写作质量或工具兼容。

工作台选择连接、账号和单专家/专家团，输入主题，检查预算与数据发送说明后提交。所有成员共享本次选定模型连接；成员默认模型与独立试运行尚未实现。成功稿可按修改要求生成新分支，冻结原配置、每轮独立预算，不覆盖原稿，详见 [15 草稿继续创作](./15-draft-continuation.md)。这不是完整聊天、交互确认或失败任务续跑。

## 2. 模型协议与安全

- 当前仅实现非流式 Chat Completions 文本与 function tools；不是 Responses、图片或视频接口。
- 输出参数可选 `max_completion_tokens` 或 `max_tokens`，不假设所有兼容服务都支持同一种参数或工具协议。
- 请求使用 Bearer Key。密钥经 AES-256-GCM 加密保存，AAD 绑定 owner 与连接 ID；普通响应、快照、SSE、队列和导出没有密钥。
- 每次发请求前重新检查连接启用状态、URL 和全部 DNS 地址；将已验证 IP 绑定实际 socket，HTTPS 仍验证原主机证书。不跟随重定向，不进行 SDK/HTTP 隐式重试。
- 单请求超时 60 秒，响应最大 1 MiB，每次最多 8 个工具请求。未完整结束、响应损坏、断线和不确定 HTTP 错误保守归为结果未知。
- 连接最多 20 个，可启停；编辑、删除、密钥轮换和主密钥版本迁移尚未开放。丢失主密钥无法解密原凭证。

模型接收本次主题、账号人设、专家方法、成员任务、依赖结果及按需读取的技能资料；修改分支还包含直接来源正文与本轮修改要求。它们离开服务器进入所选服务商；用户需自行核验服务条款、数据使用与计费。界面不展示模型内部思维过程。

## 3. Skill 与只读工具

初始上下文仅提供该成员可用技能的名称、描述与版本。预加载项在首次调用前读取完整指令；其他项由模型调用 `load_skill({key})` 按需读取。`read_skill_file({key,path})` 只读取已加载技能快照内 `references/` 或 `assets/` 下的 UTF-8 文本，单次最大 32 KiB。

服务端拒绝未绑定技能、未加载技能的资料、越界路径、脚本、二进制及未知工具。工具没有网络、Shell、服务器文件系统或桌面权限。包内声明、提示词和 `allowed-tools` 不能扩大后端权限；脚本/MCP/浏览器/外部检索仍不支持。

配置快照保留 `skillSelection.available/preloaded/loaded`；其中 `loaded` 是创建时事实，不在执行后改写。实际已加载项在 `execution.agents[].loadedSkillKeys`，实际版本来自不可变 `snapshot.skills`。工具输入、返回内容、执行/拒绝状态单独保存。不得把配置为可用或预加载等同于实际执行、事实核验或输出被用户采用。

## 4. 独立成员与阶段

每位成员有独立 AgentRun、上下文、轮次、调用账本和原始结果。同阶段最多 3 位并发，阶段之间串行；后阶段只在前置成员全部成功后运行。主理人最后单独调用，接收全部成员结果并汇总为候选正文。

没有阶段配置时，默认非主理人成员独立工作后由主理人汇总。结构化配置产生派工/回报消息，不是模型已经动态拆解或追问的证据。修改稿会重新运行整团，各成员独立获得来源正文与要求。新增显式 `team-dynamic-v1` 的受限动态派发、追问、用户确认与等待恢复见 [16 动态协作](./16-dynamic-team-collaboration.md)；旧 `team-v1` 语义不变，成员不同模型仍未实现，也不能据此宣传完整自主专家团。

Worker 并发 2 个业务任务；每个任务的成员并发上限与全局调用/Token 预算共同限制扇出。成员轮次为 1–200，默认 12；最后一轮不继续开放工具。任何成员失败会停止后续阶段，已确认成员交付和调用证据保留。

## 5. 预算与外部调用账本

提交时保存非敏感模型配置、专家/成员/技能快照与运行预算：

| 项目          | 默认   | 允许范围     |
| ------------- | ------ | ------------ |
| 模型调用次数  | 24     | 1–100        |
| 总 Token 预算 | 200000 | 2000–1000000 |
| 总运行秒数    | 600    | 30–1800      |
| 连接输入上限  | 16000  | 1000–64000   |
| 单次最大输出  | 4096   | 256–16000    |

每次请求先在事务中保存 invocation ID、Agent+turn 唯一约束、请求摘要和预算预留，再标记 `in_flight` 并发出 HTTP。保守输入预留采用请求 JSON 的 UTF-8 字节数 + 1024，再加最大输出；不是精确 tokenizer。可能提前拒绝很大的中文上下文，不自动截断依赖结果。

成功后按服务商报告的输入/输出 usage 记账；usage 缺失时按预留量保守记账。未知调用保留预留，不把断线显示成零费用。调用计数包括已预留但未发送的记录；账本区分 `reserved/in_flight/succeeded/rejected/unknown`。

这是 Token/调用次数限制，不是人民币费用硬上限。服务商用量可能有误差或超出预留，实际账单以服务商为准。没有价格表、跨任务账户额度或自动账单对账。

成功稿的修改分支沿用原限额，建立新任务、时间窗口、调用与用量账本，不共用旧任务余额。提交按钮提示新增调用与可能费用；不自动提交，不静默升级 mock，不通过修改要求授权新工具。

## 6. 取消、恢复与人工核对

状态为 `queued -> running -> succeeded / failed / cancelled / needs_review`；动态模式另有 `running -> waiting_user -> queued`，等待非终态且可取消。`succeeded` 只代表候选正文通过结构校验，不代表人工审核或发布。

- 排队取消不发模型请求；运行取消设置持久化标记，Worker 心跳尽力中断在途 HTTP 并停止新步骤。已发送请求可能仍被服务商执行和收费。
- Worker 每秒心跳，租约 30 秒，token fencing 拒绝过期 Worker 覆盖结果；最多领取 3 次，不承诺 exactly-once。
- 恢复时仅复用摘要一致且已确认成功的调用结果；未发送 reservation 可继续或释放。发现 `in_flight/unknown` 即进入 `needs_review`，不自动重发。
- 用户对照服务商日志/账单填写 10–2000 字核对说明，关闭为 `cancelled + UNKNOWN_ACKNOWLEDGED`。说明是追加记录，unknown 调用及预留证据仍保留，不代表系统验证了未扣费、导回了结果或自动续跑。
- 新建任务是新的收费操作。当前没有失败任务重试/继续按钮或供应商查询适配器，不能为了“跑完”清空账本再调用。

任务详情在一致性数据库事务中读取 revision、成员、工具、调用、消息与核对历史。SSE 发送完整最新快照；终态主动断开，不提供 Token 流或历史事件回放。

## 7. 部署与验证边界

Compose 的 API 与 Worker 连接 `private` 与 `model_egress`，API 用于显式连接检查，Worker 用于创作；数据库/Redis 只在内部网络，只有 gateway 发布端口。`model_egress` 提供网络连通，**不是防火墙级域名白名单**，应用层仍强制 URL、DNS 和 socket 检查。更严格环境应另加出口代理/防火墙。隔离 Docker 冒烟强制 mock，并覆盖 API/Worker 网络为仅 private。

增量迁移 `1793664000000-agent-runtime.ts` 新增模型连接、成员运行、调用、工具、消息、核对记录及运行预算列；不改写历史配置/正文，拒绝破坏性 down。升级前备份数据库和主密钥，先核对在途调用。

集成测试使用真实 PostgreSQL、Redis 和本地 HTTP 协议 fixture，验证独立请求、并行门禁、工具加载、拒绝、预算、取消、未知与恢复；浏览器使用 API fixtures。**没有调用收费服务商，没有证明真实模型创作质量、所有兼容 API 的互操作、Docker 启动或备份恢复。** 当前数据与测试结果见 10，完整对齐剩余项见 13。
